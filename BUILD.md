# Сборка и проверка иммерсивного OpenXR (Quest 3)

Этот гайд описывает сборку и запуск версии, где рендер идёт в **OpenXR stereo views** (левый/правый глаз отдельно), а не в плоский Android-экран.

## 1) Необходимые инструменты

- JDK 17
- Android Studio Iguana или новее
- Android SDK Platform 34
- Build Tools 34.x
- NDK 26.x
- CMake 3.22.1
- Meta Quest 3 с включённым режимом разработчика и USB-отладкой
- `adb` в PATH

## 2) Включите режим разработчика на Quest 3

Это делается один раз.

1. Войдите в [Meta for Developers](https://developer.meta.com/) и создайте (или присоединитесь к) организацию.
2. В приложении Meta Horizon на телефоне откройте ваш Quest 3.
3. В настройках устройства включите **Developer Mode**.
4. Подключите шлем по USB-C и подтвердите **Allow USB debugging** в шлеме.

Проверка:

```bash
adb devices
```

Должно появиться устройство со статусом `device`.

## 3) Откройте проект

1. Запустите Android Studio.
2. Откройте каталог:
   - `C:\Users\algoi\Downloads\1234\VIBE-CODING EXAMPLE`
3. Дождитесь синхронизации Gradle.

## 4) Сборка APK

### Через Android Studio

1. Build Variant: `debug`
2. **Build > Build APK(s)**
3. APK будет в:
   - `app/build/outputs/apk/debug/app-debug.apk`

### Через терминал

```powershell
.\gradlew.bat assembleDebug
```

Если wrapper отсутствует:

```bash
gradle wrapper
```

## 5) Установка на Quest 3

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 6) Первый запуск

1. Откройте приложение в **Unknown Sources**.
2. Выдайте разрешения:
   - `android.permission.CAMERA`
   - `horizonos.permission.HEADSET_CAMERA`
3. Наденьте шлем и дождитесь входа в иммерсивный режим.

## 7) Управление в шлеме (OpenXR actions)

- **Левый стик X**: поворот левого глаза
- **Правый стик X**: поворот правого глаза
- **Кнопка X**: переключить зеркало по X для левого глаза
- **Кнопка A**: переключить зеркало по X для правого глаза

## 8) Чеклист «работает как задумано»

1. Приложение входит в VR-режим (не плоская 2D-панель как основной вывод).
2. Левая и правая картинка реагируют **независимо**:
   - изменения левого стика не меняют правый глаз;
   - изменения правого стика не меняют левый глаз.
3. Кнопки X/A переключают зеркалирование отдельно по глазам.
4. После сворачивания/возврата приложение продолжает рендер.
5. При повторном запуске нет зависания камеры и повторного запроса OpenXR-сессии с ошибкой.
6. Если доступна одна камера, это явно видно в логах, и приложение не падает.

## 9) Диагностика swapchain/input/camera

### 9.1 Проверка выбора swapchain формата

В `logcat` должна быть строка вида:

- `Selected swapchain format: ...`

Если вместо этого появляется ошибка про отсутствие подходящего формата, runtime не поддержал ожидаемые GLES-форматы.

### 9.2 Проверка OpenXR input bindings

В рабочем случае стики и кнопки X/A меняют параметры по глазам.  
Если рендер есть, но input не работает, ищите в логах:

- `Input bindings disabled`
- `Action sets attach failed`
- `xrSyncActions failed`

Это означает fallback-режим: приложение продолжает рендер без controller input.

### 9.3 Проверка camera mapping и fallback

В `logcat` ищите диагностические строки:

- `cameraId=... facing=... capabilities=...`
- `Выбраны камеры L=..., R=...`
- `Доступна одна камера ... Включается fallback single-stream`

Если доступен только один поток камеры, оба глаза рендерятся корректно, но источник изображения может совпадать.

## 10) Ограничения и важные замечания

- Доступ к физическим потокам камер зависит от политики Horizon OS и прошивки.
- На некоторых версиях прошивки приложению может отдаваться один поток камеры. Тогда геометрически рендер останется eye-by-eye, но источник картинки может совпадать.
- Без реального прогона на вашем Quest 3 гарантировать отсутствие device-specific нюансов нельзя.

## 11) Логи при проблемах

```bash
adb logcat | grep -i -E "invertoscope|openxr|xr|camera|egl|gles"
```

Прикладывайте:

- полный текст ошибки сборки;
- вывод `adb install`;
- 30-60 секунд `adb logcat` вокруг запуска.
